# 2026-09-28 现状基线

本文件记录创建 Agent-VideoNote 时已经由多个 Agent / 多个项目实战确认的事实。

## 旧系统实际形态

旧系统已经不是 VideoNote-MCP 自动生成笔记。

实际生产链大体是：

```text
本地视频 / 字幕
→ 时间轴
→ Agent 全文阅读
→ 疑词证据仲裁
→ 视觉状态发现
→ 广告/水印处理
→ 图片与正文语义对位
→ 覆盖检查
→ 交付
```

VideoNote-MCP 在其中主要剩下 ASR 托管、任务提交、时间轴、部分状态/缓存等底层作用。

## 已验证有价值的能力

- 有可靠时间码字幕时优先使用，不无意义重转写。
- 无字幕时使用本地主 ASR。
- Fun-ASR-Nano-2512 已用于主转写。
- Qwen3-ASR-1.7B 适合有边界的疑难片段复核。
- FFmpeg / ffprobe 是高频核心工具。
- 任务状态必须持久化，不能依赖聊天记忆。
- 机械覆盖检查有价值，但不能证明文本语义正确。
- 图片需要按内容对位，不能仅按截图时间机械插入。
- 修改已有交付物前需要可靠回退点。

## 已确认的结构性问题

- 已解决问题经常只留在某个 Agent 会话或某个任务目录。
- 去广告产生大量一次性脚本，换会话后重复造轮子。
- Qwen 局部复核曾出现每个窗口重新加载模型，造成大量冷启动时间。
- 工作流、实际磁盘交付和历史状态存在漂移。
- 运行目录曾同时承担模型、数据库、缓存、实验、任务、备份和临时文件，导致严重膨胀。
- 已完成任务可能因为换 Agent / 换会话被重新检查或重新执行。
- 原 VideoNote-MCP 大量产品能力对当前本地课程流程无实际价值。

## Agent-VideoNote 的既定方向

- 重新独立实现，不迁移 VideoNote-MCP 源代码。
- 第三方能力从各自上游直接接入。
- 模块化，不做单体“大总管”。
- 本地视频优先。
- 工作流按阶段加载，不要求每轮背完整长规则。
- 普通 PROCESS 只调用已有能力，不现场重构正式工具。
- 运行数据与源码彻底分离。
- GPT 图像 AI 不进入默认工作流。
- 第三方代码与模型许可证单独审计，为未来商用留出清晰边界。
